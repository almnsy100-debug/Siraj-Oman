# سراج عُمان الرقمي | مدرسة سعود بن عزان

منصة معرفية تفاعلية تقدم تاريخ وتراث سلطنة عُمان ومعالمها، مع عناية بولاية جعلان بني بوحسن.

## الواجهتان

- **واجهة الزائر:** [فتح المنصة](https://almnsy100-debug.github.io/Siraj-Oman/) — للتصفح والتعلم والاطلاع دون أزرار إضافة أو تعديل.
- **واجهة المدير:** [تسجيل الدخول والإدارة](https://almnsy100-debug.github.io/Siraj-Oman/admin.html) — بعد التحقق من Firebase تظهر **نفس واجهة الزائر الأصلية** داخل وضع المدير، مع أزرار الإضافة والتعديل والحذف بجوار محتويات الأقسام وشريط أدوات إدارة جانبي. تُحفظ التعديلات في Firestore.
- زر **⚙ الإعدادات** أعلى واجهة الزائر ينقلك مباشرة إلى صفحة تسجيل الدخول.

## تفعيل الإدارة الآمنة

**الواجهة والملفات منشورة، لكن تسجيل الدخول ونشر المحتوى السحابي غير مفعلين حتى يكتمل إنشاء مشروع Firebase مستقل.**

اقرأ [ADMIN_SETUP.md](./ADMIN_SETUP.md) ثم:
1. إنشاء مستخدم مدير في Firebase Authentication (Email/Password).
2. نشر [firestore.rules](./firestore.rules) وإضافة وثيقة صلاحية `admins/{uid}` بقيمة `active=true`.
3. إدخال إعدادات مشروع Firebase العامة في [siraj-config.js](./siraj-config.js) بدون أي كلمة مرور.
4. مراجعة المحتوى النموذجي واستيراده من `starter-content.json` عند الحاجة.

لا تحفظ كلمة المرور في GitHub، ولا تعتمد على إخفاء أزرار الواجهة وحده لحماية البيانات.

## حدود المنصة

يدعم الموقع قراءة المحتوى والإنجاز المحلي للزوار دون أدوات تعديل. وتتيح لوحة المدير، بعد تسجيل الدخول بصلاحية الإدارة، إضافة وتعديل وحذف المقالات والفيديوهات وروابط الدروس والأعمال ووسائط جعلان والمتحف والشخصيات والمعالم والمحافظات ومحطات الرحلة وأسئلة التحدي، مع نشر المحتوى عبر Firestore. **يجب نشر النسخة الأحدث من firestore.rules يدويًا عبر Firebase Console للسماح بنشر الأقسام الإضافية.** رفع ملفات الوسائط الكبيرة ونماذج 3D نفسها وتوحيد تقدم الطلبة تحتاج تطويرًا إضافيًا.

المستودع مستقل عن المستودع القديم.

## طريقة تحرير المحتوى من نفس التصميم

1. يفتح الزائر الرابط العام فيشاهد جميع الأقسام ويتفاعل دون ظهور أزرار التعديل والحذف.
2. يضغط المسؤول «⚙ الإعدادات» ويسجّل الدخول، فتظهر واجهة سراج نفسها بالتصميم والأقسام الأصليين مع أدوات إضافة/تعديل/حذف داخل الأقسام.
3. في أول تعديل لقسم لم يُنشر محتواه في Firestore، تعرض الإدارة خيار نسخ المواد الأصلية إلى قاعدة البيانات حتى لا تختفي.
4. يتولى Firestore التحقق من صلاحية الكتابة؛ وجود أزرار في الواجهة لا يمنح زائرًا حق التعديل.
5. بعد الحفظ تعيد واجهة المدير تحميل العرض، ويستطيع الزائر مشاهدة البيانات المنشورة بعد تحديث الصفحة.

**تنبيه:** الأقسام التفاعلية الإضافية تتطلب إعادة نشر قواعد `firestore.rules` المحدّثة في Firebase Console. ملفات الصور والفيديو الكبيرة والمجسمات تحتاج مسار تخزين سحابي منفصل، وأدوات تحرير المحتوى النصي لا ترفع تلك الملفات حاليًا.

## إضافة الصور مباشرة من محرر الإدارة

أضيف إلى محرر الأقسام المدعومة حقل **رابط صورة HTTPS** وزر **اختيار صورة من الجهاز** مع معاينة، وإزالة الصورة. الصور المحلية تُحوَّل في المتصفح إلى WebP مصغر (حتى 640 بكسل وطول بيانات أقل من 48 ألف حرف) ثم تُحفظ داخل حقل `imageUrl` في وثيقة محتوى القسم الموجودة في Cloud Firestore؛ لا تحتاج هذه الآلية إلى Cloud Storage أو خطة Blaze، لكنها مخصصة للصور التعليمية الصغيرة وليست ألبوم صور عالي الدقة. يتم حفظ أول إطار من GIF، ولا تُحفظ الحركة. حدود المستند في Firestore تمنع استعمال مئات الصور بهذه الطريقة؛ للصور الكثيرة أو عالية الجودة يُنصح باستضافة صور مستقلة.

يعرض `index.html` الصور الجديدة في القاعات والشخصيات والمعالم والدروس والمقالات والفيديوهات وأعمال الطلبة والمحافظات ومحطات الرحلة مع إبقاء التصميم الأصلي عند عدم وجود صورة. يتطلب نشر الصورة نجاح الحفظ إلى Firestore وفق قواعد الصلاحيات.
